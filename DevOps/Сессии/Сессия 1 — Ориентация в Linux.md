## Ключевые выводы

> [!important] `wc -l` считает символы перевода строки, а не «строки»
> `printf "a\nb"` → `wc -l` показывает **1**, хотя глазами строк две. `echo -e "a\nb"` добавляет `\n` в конец → **2**.

- При передаче в пайп `ls` сам печатает по одному имени на строку. `ls -1` фиксирует это явно, но в пайпе не обязателен.
- `>` перезаписывает файл, `>>` дописывает, `2>` перенаправляет поток ошибок.
- `grep -c` считает **строки** с совпадением, `grep -o ... | wc -l` — вхождения.
- `less`: `q` — выход, `/` — поиск, `G` — конец, `g` — начало.
- Текущий каталог не входит в `PATH`, поэтому скрипт запускается как `./script.sh`.

## Решение мини-задачи

```bash
mkdir -p ~/devops/lesson1/logs
printf "INFO start\nERROR db down\nINFO retry\nERROR timeout\nERROR db down\n" > ~/devops/lesson1/logs/app.log
grep -c ERROR ~/devops/lesson1/logs/app.log   # 3
```

## Проверка знаний

| Команда | Ответ |
|---|---|
| `grep -vc INFO logs/app.log` | `2` |
| `grep ERROR logs/app.log \| wc -l` | `3` |
| `echo -e "a\nb" \| wc -l` | `2` |
| `printf "a\nb\n" \| wc -l` | `2` |
| `ls /etc \| wc -l` | `237` (на этой машине) |
