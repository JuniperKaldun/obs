# Сессия 3 — Процессы

← [[DevOps]] · [[Дорожная карта]]

## Цель

Уметь увидеть, что запущено на машине; остановить процесс правильно; понять, почему он не умирает.

## Что разобрано

- [x] `ps aux`, `ps -ef`, `pgrep -a`, сортировка по памяти и CPU
- [x] `top`: `load average`, сортировки `P` и `M`, выход `q`
- [x] Фоновые задания: `&`, `jobs`, `kill %N`, `bg`, `fg`
- [x] `Ctrl+Z` (TSTP, заморозка) против `Ctrl+C` (INT, завершение)
- [x] Сигналы `TERM` (15) и `KILL` (9), почему `-9` — крайняя мера
- [x] `nohup` и почему процесс без него умирает с терминалом
- [x] Службы: `systemctl status`, `list-units`

## Ключевые выводы

- `kill -9` нельзя перехватить: процесс не закрывает файлы, не дописывает логи, не снимает блокировки.
- `Ctrl+Z` не убивает, а замораживает — память остаётся занятой. Завершает `Ctrl+C` или `kill`.
- `kill %1` работает только в **текущей** оболочке. В новом терминале таблица заданий пуста → нужен PID: `$!` или `pgrep`.
- `pgrep -f` ищет по всей командной строке; без `-f` имя `trap.sh` не находится, потому что процесс называется `bash`.

## Грабли, на которые наступили

| Ошибка | Причина | Решение |
|---|---|---|
| `trap` в одну строку не работает | `\"` внутри одинарных кавычек не экранирует | heredoc `<<'EOF'` в файл |
| `kill %1: нет такого задания` | другая оболочка или задание уже завершилось | `$!`, `pgrep`, `jobs -l` |
| `pkill: операция не позволена` | процесс запущен через `sudo`, принадлежит root | `sudo pkill` или запускать без `sudo` |
| `list of process IDs must follow -p` | `$(pgrep ...)` вернул пустоту | сначала `pgrep -a`, потом убивать |

## Проверка знаний

1. `Ctrl+Z` замораживает, `Ctrl+C` завершает — верно; но оба сигнала процесс может перехватить.
2. `kill -9` убивает мгновенно и без обработки — верно.
3. Фоновый процесс без `nohup` получает `SIGHUP` при закрытии терминала — верно.
